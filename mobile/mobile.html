Cythera

Moving and acting

The two floating windows are the numeric keypad and Cythera's action keys. Drag a window by its ≡ header, resize it from the corner, or press Gestures in its header to swap the buttons for a thumb control. The settings panel moves the same way — drag its ≡ bar to put it somewhere it is not in the way, or tap the bar to fold it down to a strip. Pads hides both floating windows, which is what you want once you are using a keyboard; Reset puts everything back where it started. Where you leave them is remembered on this device.

    Touching the screen

    These three settings describe what a finger does. Direct puts the pointer where your finger is — best for the game world. Trackpad moves the pointer relatively and holds for 0.4 s to start a drag — best for menus and small targets. Pan View keeps the pointer on the crosshair and moves the view instead. Two fingers pinch to zoom anywhere, and a two-finger tap is a right-click.

    Mouse and keyboard

    A mouse already points, so it is always Direct — the pointer inside the Mac follows yours, including while no button is down, and both buttons go through as themselves. Trackpad means nothing to a mouse and is ignored by one; Pan View still applies, and there a drag moves the view. The scroll wheel zooms, which is the desktop half of the pinch.

    Your keyboard is passed straight to the emulated Mac, so Cythera's numeric keypad and its letter commands work as they did on the original — the floating windows are for when you have no keyboard, not instead of one. The browser keeps F5, F11, F12 and its own reload/new-tab/close shortcuts. Everything on this page can also be reached with Tab and Enter.

    The picture

    Crisp shows the emulator's own pixels, unaltered. Undith runs the same undither the data viewer uses on the game's artwork. Mac OS draws a shade it has no palette entry for as a checkerboard of two colours it does have; this reads that pattern back as the tone it was standing in for, and can tell it apart from linework, so a one-pixel highlight survives where a blur would have taken it. It needs WebGL.

    Loading your own Cythera

    Open takes a file from this device — a disk image, an .hqx, anything. So does dropping a file anywhere on this page, and so does Send that disk to mobile.html in the data viewer, which hands over an edited archive as a disk without going through your Downloads folder at all. However it arrives, it lands in a card at the bottom of the screen with one step left: drag the card onto the screen.

    File is the one that works on a phone. It hands the whole window to the emulator's own page for a moment so you can tap its Load File control, which opens your Files app. Nothing restarts and nothing running is lost. The file has to be saved to the device first, which is what Save the file on the card is for — the Mac's picker reads your file system, not this page's memory.

    Why the detour, rather than this page simply loading the file: the emulator will take a disk from a URL, but infinitemac.org's own server is what fetches that URL, not your browser, so it can never see a file on your device. The only other route is a real drop onto the emulator, and a drop belongs to the page being dropped on, which is infinitemac.org's and not this one — no page can start that drop for you, and on a touch screen there is no drag to start. So the file picker inside the emulator is the door, and this page's job is to get you to it.

    Drag a file onto the emulator — a disk image (.dsk, .img, .iso) mounts, and anything else, including the Cythera.hqx and Cythera Data.hqx in this project's sources/ folder, is copied into the emulated Mac's Downloads folder for StuffIt Expander to unpack. This is a desktop-only path: it is the emulator's own file drop, and phones have nothing to drag with.

    Disk loads a disk image from a URL. The URL has to be reachable from the public internet, because infinitemac.org's own server fetches it in ranges — it is not your browser doing the download, so a file:// path or a private address will not work.

    The same archive this emulator runs can be taken apart, resource by resource, in the data viewer beside this file — it reads Cythera Data.hqx directly.

    Playing your own edits, in two moves. The viewer can edit a resource and write the whole archive back out, and its Data file menu hands you the result as a .dsk disk image. Drag that onto the emulator, then press Install in this panel. The disk carries an AppleScript as well as the archive; Install types at the emulated Finder — no pointer, so nothing depends on where the windows are — until Script Editor is running it, and the script finds the folder holding the Cythera application on any mounted disk, replaces the Cythera Data in it, and starts the game. It takes about forty seconds and the toast says where it has got to.

    It types, so leave the Finder in front while it runs; whatever is frontmost gets the keystrokes. If you would rather do it by hand, everything it does is a drag from the export disk's window into the game's folder, and the script is readable — open Install and Play on the disk and Script Editor shows it. Mac OS may say it could not rebuild the export disk's desktop file; the disk is read-only, that is what it does, and the files are fine.

    The URL

    This page reads ?cdrom=, ?disk=, ?machine= and ?speed=, so a particular build of the game can be bookmarked. Your window layout and settings are remembered on this device. ?handoff=1 is what the data viewer's Send that disk to mobile.html opens: it collects the disk image that page left for this one and puts it in the card at the bottom of the screen.
